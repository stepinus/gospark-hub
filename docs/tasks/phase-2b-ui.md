# phase-2b-ui: настройки реестров и локальные рецепты в интерфейсе

Читать вместе с `docs/tasks/phase-2b-registries.md` (полный план, §4, §5).

## Цель

Страница «Settings» с формой источников и блоком локальных рецептов; в карточке
рецепта — бейдж происхождения, кнопка «Создать копию», кнопка «Удалить» у
локальных с окном подтверждения.

## Контракт API (уже согласован, реализуется параллельно)

```
GET    /api/registries            -> {sources:[{id,url,ref,subpath,commit,synced_at,error,recipes}], local_count, syncing}
POST   /api/registries            {urls:"a, b"}  -> {sources:[...], errors:[{url,error}]}
POST   /api/registries/sync       -> {sources:[...]}
POST   /api/registries/{id}/sync  -> {source:{...}} | 404
DELETE /api/registries/{id}       -> {deleted:true}
GET    /api/local-recipes         -> {recipes:[{slug,name,origin,modified}]}
POST   /api/recipes/{slug}/fork   {slug:"new-slug"} -> {slug:"new-slug"} | 409 {detail}
DELETE /api/recipes/{slug}/local  -> {deleted:true} | 409 {detail}
```

Рецепт в `GET /api/recipes/{slug}` получает поле `"local": true|false`
(добавляется бэкендом; если поля ещё нет — считать `false`).

## Файлы в скоупе

- `frontend/src/pages/Settings.jsx` — новый.
- `frontend/src/App.jsx` — маршрут `/settings` + пункт навигации для админа.
- `frontend/src/pages/RecipeDetail.jsx` — бейдж, «Создать копию», «Удалить».
- `frontend/src/lib/api.js` (или где лежат вызовы) — новые эндпоинты.
- `frontend/src/index.css` — только если нужны новые классы, в стиле существующих.

## Не трогать

`internal/**` (любой Go-код), `registry/**`, `docs/**`, `package.json`
(новых зависимостей нет — только React, который уже есть).

## Требования

1. Форма источников: `textarea`, плейсхолдер с примером
   `https://github.com/owner/repo/tree/main/registry/recipes`, подсказка «через
   запятую или с новой строки». После отправки — список источников с URL, веткой,
   коротким коммитом, «синхронизировано N назад», ошибкой красным, кнопками
   Sync и Remove (Remove с подтверждением).
2. Кнопка «Синхронизировать все», состояние загрузки на время запроса.
3. Блок «Локальные рецепты»: слаг, откуда скопирован, дата; кнопка «Удалить» →
   модальное окно: заголовок «Удалить рецепт <name>?», текст «Файлы будут удалены
   из ~/.config/gospark/registry/local/<slug>», кнопки «Отмена» (фокус по
   умолчанию, закрывается по Escape) и красная «Удалить».
4. `RecipeDetail`: бейдж «Локальный» рядом с названием, если `local`; кнопка
   «Создать копию» открывает поле для нового слага (валидация
   `^[a-z0-9][a-z0-9-]{1,62}$`), при 409 показывает текст ошибки; кнопка
   «Удалить» видна только для локальных и использует то же модальное окно.
5. Ошибки API показываются текстом в форме, без падения страницы; 403 (не админ)
   — сообщение «Нужны права администратора».
6. Никаких новых npm-зависимостей, стиль — существующие Tailwind-классы.

## Готово когда

```
npm run build     # в frontend/, без ошибок
npm run lint      # если скрипт есть, без новых замечаний
```
плюс скриншот страницы `/settings` и карточки локального рецепта с открытым окном
подтверждения, и один коммит:

```
git add -A && git commit -m "UI: настройки реестров, копия и удаление локальных рецептов"
```
